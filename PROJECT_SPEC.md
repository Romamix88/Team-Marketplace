## Автономная команда для управления кабинетом Wildberries

Версия: 4.0 | Дата: 02 апреля 2026

## 1. Wildberries API

### 1.1. Общие сведения
- Wildberries предоставляет REST API для управления кабинетом продавца
- Авторизация: Bearer token (API-ключ из личного кабинета WB)
- Базовые URL-ы зависят от раздела API
- Rate limits: зависят от эндпоинта (обычно 10-100 запросов/мин)
- Формат: JSON

### 1.2. Разделы API по модулям MCP-сервера

**Модуль `warehouses` — Склады и поставки:**
- `GET /api/v3/warehouses` — список складов продавца
- `GET /api/v3/stocks/{warehouseId}` — остатки по складу
- `PUT /api/v3/stocks/{warehouseId}` — обновление остатков
- `GET /api/v3/supplies` — список поставок
- `POST /api/v3/supplies` — создание новой поставки
- `GET /api/v3/supplies/{supplyId}` — детали поставки
- `PATCH /api/v3/supplies/{supplyId}/deliver` — передача поставки в доставку
- `GET /api/v3/supplies/{supplyId}/orders` — заказы в поставке
- `PUT /api/v3/supplies/{supplyId}/orders/{orderId}` — добавление заказа в поставку
- `GET /api/v3/offices` — список пунктов приёма WB
- Коэффициенты приёмки, лимиты по складам

**Модуль `content` — Карточки товаров:**
- `POST /content/v2/get/cards/list` — список карточек (пагинация, фильтры)
- `POST /content/v2/cards/update` — обновление карточки (описание, характеристики)
- `GET /content/v2/object/all` — справочник категорий
- `GET /content/v2/object/charcs/{subjectId}` — характеристики категории
- `POST /content/v2/cards/upload` — создание новой карточки
- `POST /content/v2/tag/nomenclature/link` — привязка тегов
- Медиафайлы: загрузка фото/видео через отдельный эндпоинт

**Модуль `prices` — Цены и скидки:**
- `GET /api/v2/list/goods/filter` — текущие цены на товары
- `POST /api/v2/upload/task` — загрузка новых цен (массово)
- `GET /api/v2/list/goods/size/nm` — цены по размерам
- Управление скидками, акциями

**Модуль `advertising` — Реклама:**
- `GET /adv/v1/promotion/count` — количество кампаний по статусам
- `GET /adv/v1/promotion/adverts` — список рекламных кампаний
- `POST /adv/v1/save-ad` — создание кампании
- `GET /adv/v1/stat/words` — статистика по ключевым словам
- `POST /adv/v2/fullstats` — полная статистика кампаний (показы, клики, CTR, CPC, расход)
- `POST /adv/v1/start` — запуск кампании
- `POST /adv/v1/pause` — пауза кампании
- `POST /adv/v1/budget/deposit` — пополнение бюджета кампании
- `POST /adv/v1/cpm` — изменение ставки CPM
- Управление ключевыми словами, минус-словами

**Модуль `analytics` — Продажи и статистика:**
- `GET /api/v1/supplier/sales` — продажи за период (детализация по товарам)
- `GET /api/v1/supplier/orders` — заказы за период
- `GET /api/v1/supplier/stocks` — остатки на складах WB
- `POST /api/v1/analytics/nm-report/detail` — детальный отчёт по номенклатурам (просмотры, корзина, заказы, выкупы)
- `POST /api/v1/analytics/acceptance-report` — отчёт о приёмке
- Скорость продаж, ABC-анализ

**Модуль `finance` — Финансовые отчёты:**
- `GET /api/v5/supplier/reportDetailByPeriod` — детализированный финансовый отчёт (комиссии, логистика, штрафы, компенсации)
- `GET /api/v1/supplier/incomes` — поступления
- Стоимость хранения по товарам
- Штрафы и удержания (детализация)
- Комиссии по категориям

### 1.3. Обработка ошибок WB API
- 429 Too Many Requests → exponential backoff (1s, 2s, 4s, 8s)
- 401 Unauthorized → проверить токен, уведомить владельца
- 5xx → retry до 3 раз с задержкой
- Все ошибки логируются в structlog

## 2. MCP-сервер Wildberries

### 2.1. Назначение
Прослойка между агентами и WB API. Предоставляет типизированные инструменты (tools) для каждого агента. Не хранит данных — каждый запрос обращается к WB API.

### 2.2. Размещение
Docker-контейнер на VPS. Python 3.11+, httpx (async HTTP-клиент).

### 2.3. Модульная структура
Один сервер, модули — отдельные файлы. Добавляются по фазам.

### 2.4. Защита доступа
Каждый агент видит только свои инструменты — конфигурация в `auth/access.py`:
```python
AGENT_ACCESS = {
    "agent-wb-logistics": ["warehouses", "analytics"],
    "agent-wb-content": ["content", "analytics"],
    "agent-wb-marketing": ["advertising", "analytics"],
    "agent-wb-analyst": ["analytics", "prices", "finance"],
    "agent-wb-accountant": ["finance", "analytics"],
    "agent-wb-manager": ["warehouses", "content", "prices", "advertising", "analytics", "finance"],
}
```

## 3. Redis — шина сообщений

### 3.1. Назначение
Коммуникация между агентами. Руководитель создаёт задачи, агенты берут и выполняют.

### 3.2. Паттерны использования
- **Очереди задач**: каждый агент слушает свою очередь (`tasks:agent-wb-analyst`)
- **Pub/Sub**: широковещательные уведомления (новые данные, алерты)
- **Shared state**: общие данные (текущие остатки, цены, метрики) в Redis hash/sorted sets

### 3.3. Модель задачи
```python
class Task(BaseModel):
    id: str                          # UUID
    type: str                        # "analyze_sales", "create_supply", etc.
    created_by: str                  # agent-wb-manager
    assigned_to: str                 # agent-wb-analyst
    status: TaskStatus               # pending, in_progress, completed, failed
    priority: int                    # 1-5 (1 = highest)
    payload: dict                    # Параметры задачи
    result: dict | None              # Результат выполнения
    created_at: datetime
    completed_at: datetime | None
    requires_approval: bool          # Нужно ли одобрение человека
```

### 3.4. Размещение
Docker-контейнер на VPS. Redis 7+. Persistence: RDB snapshots (каждые 5 мин).

## 4. Telegram-бот

### 4.1. Назначение
- Канал связи владельца с командой агентов
- Human-in-the-loop: одобрение/отклонение критичных операций
- Получение отчётов и алертов

### 4.2. Функциональность
- **Одобрения**: inline-кнопки «Одобрить» / «Отклонить» + детали операции
- **Отчёты**: ежедневная сводка продаж, остатков, рекламы
- **Алерты**: out-of-stock, аномалии в расходах, ошибки агентов
- **Команды**: `/status` — статус агентов, `/sales` — продажи за сегодня, `/stock` — критичные остатки
- **Чат**: свободный диалог с руководителем-агентом (Фаза 3)

### 4.3. Технология
- Python, aiogram 3.x
- Docker-контейнер на VPS
- Интеграция с Redis (получает запросы на одобрение, отправляет решения)

### 4.4. Безопасность
- Whitelist chat_id (только авторизованные пользователи)
- Логирование всех одобрений/отклонений
- Timeout: если нет ответа 30 мин → повторное уведомление

## 5. Веб-дашборд

### 5.1. Назначение
Детальный мониторинг всей команды агентов, аналитика, история действий.

### 5.2. Функциональность
- Статус всех агентов (online/offline, последний heartbeat)
- Лента задач (создано, в работе, выполнено, ошибки)
- Логи действий каждого агента
- Метрики WB: продажи, остатки, реклама, финансы
- Ожидающие одобрения (дублирование Telegram)
- Настройки: пороги алертов, расписание отчётов

### 5.3. Технология
- Backend: FastAPI (Python)
- Frontend: Jinja2 + HTMX (минимальный JS, серверный рендеринг)
- Docker-контейнер на VPS
- Авторизация: простой логин/пароль (или OAuth через Telegram)

## 8. AI-агенты

### 8.1. Размещение
Docker-контейнеры на VPS. Каждый агент — отдельный контейнер.

### 8.2. LLM-провайдер — RouterAI (routerai.ru)
- Единый API-ключ для всех моделей
- Модель указывается в конфиге каждого агента
- Переключение модели — изменение одной строки
- Автоматическая отказоустойчивость
- Оплата в рублях

### 8.3. Выбор модели под агента
| Агент | Модель | Почему |
|---|---|---|
| Руководитель WB | Claude Opus 4.6 | Сложная координация, принятие решений |
| Логист | Claude Sonnet 4.6 | Анализ данных, сопоставление остатков |
| Контент-менеджер | Claude Sonnet 4.6 | Генерация текстов, SEO, креатив |
| Маркетолог | Claude Sonnet 4.6 | Аналитика рекламы, оптимизация ставок |
| Аналитик | DeepSeek V3.2 | Структурированный анализ, расчёты — экономия |
| Бухгалтер | DeepSeek V3.2 | Сверки, табличные данные — экономия |

### 8.4. Базовый класс агента (BaseAgent)
Все агенты наследуют общий класс:
- Инициализация LLM-клиента (RouterAI)
- Подключение к Redis (получение/выполнение задач)
- Подключение к MCP-серверу (вызов инструментов)
- Логирование (structlog)
- Heartbeat (регистрация в системе)
- Обработка ошибок и retry
- Human-in-the-loop (запрос одобрения через Telegram)

### 8.5. Ориентировочная стоимость RouterAI
- Пилот (2 агента, Фаза 1): 3 000-10 000 ₽/мес
- Полное развёртывание (6 агентов): 15 000-40 000 ₽/мес

## 9. Система логирования

### 9.1. Что логируется
- Каждый вызов MCP-инструмента: кто, что, когда, параметры, результат
- Каждое решение агента: входные данные, промпт, ответ LLM, действие
- Каждая операция записи: что изменил в WB (цены, контент, реклама)
- Все одобрения/отклонения human-in-the-loop (кто, когда, что)
- Ошибки, таймауты, отказы

### 9.2. Технология
- structlog (JSON-формат)
- Docker volumes для хранения
- Ротация логов: 7 дней по умолчанию

## 10. Механизм human-in-the-loop

### 10.1. Принцип
Критичные операции требуют подтверждения владельца через Telegram.

### 10.2. Критичные операции
- Изменение цен на товары
- Создание/остановка рекламных кампаний
- Изменение рекламного бюджета
- Создание поставок FBO
- Изменение контента карточек (описания, заголовки)

### 10.3. Как работает
1. Агент формирует действие и отправляет запрос на одобрение
2. Telegram-бот отправляет сообщение с деталями + inline-кнопки
3. Владелец нажимает «Одобрить» или «Отклонить»
4. Агент получает решение через Redis и выполняет/отменяет действие
5. Всё логируется

### 10.4. Эволюция
- Начало: подтверждение для ВСЕХ критичных операций
- Со временем: автоматизация рутинных операций ниже порога
  - Например: изменение ставок в пределах ±10% от текущей — автоматически
  - Изменение цен в пределах ±5% — автоматически

## Порядок запуска проекта

### Подготовительные действия (до Фазы 0)
1. Арендовать VPS (4 vCPU, 8 ГБ RAM, 80 ГБ SSD, Ubuntu 24.04)
2. Установить Docker + Docker Compose на VPS
3. Зарегистрироваться на routerai.ru, получить API-ключ
4. Создать Telegram-бота через @BotFather
5. Подготовить WB API-токен (уже есть)

### Фаза 0 — Фундамент (2 недели)
1. Docker Compose: Redis, MCP-WB, Telegram-бот, дашборд
2. MCP-сервер WB: модули `analytics` и `warehouses` (только чтение)
3. Базовый класс агента (BaseAgent)
4. Shared-модули: message_bus, task_manager, models, approval, logging
5. Telegram-бот: одобрения + базовые команды
6. Дашборд-заглушка: статус компонентов
7. Тестирование: получение данных из WB API

### Фаза 1 — Аналитик + Логист (3 недели)
1. MCP-WB: модули `prices` и `finance` (чтение)
2. Агент «Аналитик»: отчёты продаж, unit-экономика, рекомендации по ценам
3. Агент «Логист»: остатки WB, скорость продаж, план поставок
4. Human-in-the-loop: одобрение изменения цен и создания поставок
5. Ежедневные отчёты в Telegram
6. Тестирование → итерация

### Фаза 2 — Контент + Маркетолог (3 недели)
1. MCP-WB: модули `content` и `advertising` (чтение + запись)
2. Агент «Контент-менеджер»: анализ карточек, оптимизация, A/B тесты
3. Агент «Маркетолог»: управление рекламой, оптимизация ДРР
4. Human-in-the-loop: одобрение изменений контента и рекламных кампаний
5. Тестирование → итерация

### Фаза 3 — Руководитель + Бухгалтер (2 недели)
1. Агент «Руководитель»: оркестрация всей команды, ежедневные сводки
2. Агент «Бухгалтер»: сверка финансовых отчётов WB
3. Полноценный дашборд: все агенты, задачи, метрики
4. Опционально: MCP-1С (остатки на складе компании, себестоимость)
5. Финальное тестирование всей команды

### Масштабирование (по запросу)
- Адаптация MCP-серверов под Ozon API и Яндекс Маркет API
- Мультиплатформенный доступ для агентов
- Кросс-платформенная аналитика
