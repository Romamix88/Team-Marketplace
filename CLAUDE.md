# CLAUDE.md — Команда AI-агентов для маркетплейсов «Атмосфера»

## О проекте

Компания «Атмосфера» (~70 человек) — импорт, производство и продажа текстиля (постельное бельё, подушки, одеяла). B2B — гостиницы, B2C — маркетплейсы (WB, Ozon, ЯМ, LaModa, Золотое яблоко) и собственный сайт.

**Цель**: создать автономную команду AI-агентов, которая полностью ведёт кабинет маркетплейса и увеличивает продажи. Начинаем с **Wildberries**, далее масштабируем на Ozon и Яндекс Маркет.

Команда из 6 агентов: руководитель, логист, контент-менеджер, маркетолог, аналитик, бухгалтер. Каждый агент специализируется на своей области и взаимодействует с остальными через общую шину сообщений.

## Архитектура

### Системы компании
- **1С:КА 2.5** — склад, закупки, финансы, бухгалтерия, производство (сервер в офисе)
- **Wildberries API** — основная внешняя интеграция (статистика, контент, цены, реклама, поставки, аналитика, финансы)
- **Маркетплейсы** — WB, Ozon, ЯМ интегрированы с 1С (автосоздание заказов клиента)

### Стек
- **VPS-сервер**: вся инфраструктура агентов, MCP-серверов, дашборда — в одном месте
- **LLM**: RouterAI (routerai.ru) — единый API ко всем моделям, оплата в рублях
- **Модели подбираются под задачу каждого агента**: Claude, DeepSeek и др.
- **Redis**: шина сообщений между агентами (pub/sub + очереди задач)
- **Telegram-бот**: human-in-the-loop (одобрения), отчёты, связь с владельцем
- **Веб-дашборд**: мониторинг агентов, задачи, логи, аналитика

### Трёхуровневая архитектура
1. **Транспортный** — MCP-серверы (Wildberries API, позже 1С) — на VPS
2. **Логический** — AI-агенты с бизнес-логикой (RouterAI API) — на VPS
3. **Интерфейсный** — дашборд, Telegram-бот, уведомления — на VPS

### MCP-серверы

**MCP-сервер Wildberries** (`mcp-wb/`) — основной на старте:
- Модуль «Склады» (`warehouses`): остатки на складах WB, список складов, поставки FBO
- Модуль «Контент» (`content`): карточки товаров, описания, характеристики, медиа
- Модуль «Цены» (`prices`): текущие цены, изменение цен, скидки
- Модуль «Реклама» (`advertising`): кампании, ставки, бюджеты, статистика
- Модуль «Аналитика» (`analytics`): продажи, заказы, возвраты, скорость продаж
- Модуль «Финансы» (`finance`): финансовые отчёты, комиссии, штрафы, хранение

**MCP-сервер 1С** (`mcp-1c/`) — подключается позже (Фаза 3+):
- Модуль «Склад»: остатки на складе компании, себестоимость товаров
- Модуль «Финансы»: финансовые данные для сверки
- Подключение: VPN (WireGuard) к офисному серверу 1С

Каждый агент видит только свой набор инструментов — конфигурация доступа.

### Коммуникация между агентами
- **Redis** (pub/sub + очереди задач) — шина сообщений
- Руководитель создаёт задачи → агенты берут из очереди → публикуют результаты
- Shared state в Redis для общих данных (текущие остатки, цены, метрики)
- Агенты не обращаются друг к другу напрямую — всё через Redis

### Human-in-the-loop
- **Telegram-бот**: inline-кнопки для одобрения/отклонения, отчёты, чат с руководителем-агентом
- **Дашборд**: детальная аналитика, история действий, ручное управление
- **Критичные операции** (требуют одобрения): изменение цен, запуск/стоп рекламы, создание поставки, изменение контента карточек, изменение бюджета рекламы
- **Некритичные** (автономно): анализ данных, формирование отчётов, рекомендации, мониторинг

### RouterAI — выбор модели под агента
Единый API-ключ RouterAI, модель меняется одним параметром в конфиге агента.

| Агент | Рекомендуемая модель | Обоснование |
|---|---|---|
| Руководитель WB | Claude Opus 4.6 | Сложная координация, принятие решений, большой контекст |
| Логист | Claude Sonnet 4.6 | Анализ данных, сопоставление остатков |
| Контент-менеджер | Claude Sonnet 4.6 | Генерация текстов, SEO, креатив |
| Маркетолог | Claude Sonnet 4.6 | Аналитика рекламы, оптимизация ставок |
| Аналитик | DeepSeek V3.2 | Структурированный анализ, расчёты — дешевле |
| Бухгалтер | DeepSeek V3.2 | Сверки, табличные данные — дешевле |

Модели могут пересматриваться после тестирования — меняется одна строка в конфиге.

## Правила разработки

### Безопасность
- **Human-in-the-loop**: агенты НЕ выполняют критичных операций без подтверждения человека через Telegram
- **Принцип минимальных привилегий**: агент видит только свои инструменты MCP, каждый агент использует свой WB API-токен с доступом только к нужным разделам
- **Раздельные WB-токены**: 6 токенов (по одному на агента), MCP-сервер выбирает токен по X-Agent-Id
- **Логирование**: каждое действие каждого агента записывается
- **Разграничение прав**: чтение — всегда, запись — только для конкретных операций с одобрением
- **Откат (rollback)**: при ошибках

### Git-процесс

### Стиль кода
- Python 3.11+ для MCP-серверов и агентов
- Type hints обязательны
- Docstrings на русском
- Конфигурация через YAML-файлы, секреты через переменные окружения
- Логирование через structlog
- Все вызовы LLM через RouterAI API (единый эндпоинт, модель указывается в config.yml агента)
- HTTP-клиент: httpx (async)
- Telegram-бот: aiogram 3.x
- Дашборд: FastAPI + Jinja2
